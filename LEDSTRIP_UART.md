# Протокол LED Strip UART. Betaflight-BOOST

Документ является техническим заданием на прошивку **Arduino Nano**, принимающую состояние подсветки от полётного контроллера Betaflight-BOOST / Betaflight-BOOST-SPEC и управляющую лентой WS2812 (или совместимой).

Полётный контроллер **не** формирует временную диаграмму WS2812. Он передаёт текстовые кадры UART. Ведущим устройством ленты является Arduino.

Готовый пример прошивки Arduino Nano входит в комплект SPEC: `arduino/ledstrip_uart.ino` (в корне репозитория — `arduino/ledstrip_uart/ledstrip_uart.ino`). Библиотека: Adafruit NeoPixel.

---

## 1. Аппаратная часть

### 1.1. Соединения

| Вывод полётного контроллера | Arduino Nano | Примечание |
|---|---|---|
| `LED_STRIP` (ресурс LED_STRIP) | **D4** | Только линия **TX** контроллера. Линию TX Arduino к контроллеру не подключать. |
| `GND` | `GND` | Общий провод обязателен. |

Питание 5 В Arduino **не** соединять с выводами 3,3 В / 5 В / VBAT контроллера. Arduino питается от USB либо от собственного стабилизатора 5 В. Лента питается от стабилизатора 5 В с достаточной нагрузочной способностью; вывод `5V` Arduino источником питания ленты не является.

### 1.2. Уровни сигналов

- Выход GPIO контроллера — UART TX с уровнем **3,3 В**.
- Arduino Nano работает от 5 В; уровень 3,3 В на входе RX является допустимым логическим «1». Преобразователь уровней для направления «контроллер → Arduino» не требуется.
- Подача 5 В на пад LED контроллера **запрещена**.

### 1.3. Назначение пада LED

Вывод `LED_STRIP` зависит от платы и определяется командой CLI `resource`. Требуется строка `LED_STRIP`. Имена конкретных плат в настоящем документе не приводятся.

### 1.4. Настройка полётного контроллера

```
set ledstrip_output = UART
save
```

Требуется перезагрузка. После неё пад LED работает как UART, а не как выход WS2812.

Возврат к управлению лентой с контроллера:

```
set ledstrip_output = STRIP
save
```

Значение по умолчанию — `STRIP`. В сборке SPEC параметр доступен для изменения.

## 2. Канал UART

Контроллер формирует UART TX на паде LED через таймер того же вывода (как у WS2812), без занятости процессора на каждый бит. Штатный модуль UART микроконтроллера для этой линии не используется.

| Параметр | Значение |
|---|---|
| Скорость | **9600** бод |
| Формат | **8N1** (8 бит данных, без чётности, 1 стоп-бит) |
| Порядок бит | младший бит первым (стандартный UART) |
| Состояние покоя | высокий уровень |
| Старт-бит | низкий уровень |
| Стоп-бит | высокий уровень |
| Направление | только контроллер → Arduino |
| Частота кадров | около **20 Гц** (одна текстовая строка) |
| Интервал между байтами | около **2 мс** высокого уровня (пауза для SoftwareSerial) |

В комплекте SPEC приём организован через SoftwareSerial на выводе **D4** (аппаратный UART0 на D0/D1 остаётся свободным для USB):

```cpp
SoftwareSerial fcSerial(4, 3);
fcSerial.begin(9600);
```

Аппаратный `Serial` на D0 применять не требуется. Линию TX Arduino (D1 и программный D3) к контроллеру не подключать.

Приёмник обязан корректно обрабатывать:

- паузы между байтами внутри строки;
- шум и оборванные строки при включении питания;
- пропуски кадров (сохраняется последнее достоверное состояние).

---

## 3. Формат кадра

Одна строка ASCII, завершающаяся символом LF (`\n`, `0x0A`). Символ CR **не** передаётся. Контрольная сумма отсутствует.

```
L,<armed>,<boost>,<remain>,<pct>,<bright>,<id>,<r>,<g>,<b>\n
```

Все поля — целые числа без знака в десятичной записи. Пробелы отсутствуют. Префикс — латинская буква `L`.

### 3.1. Примеры

Контроллер взведён, Boost активен, осталось 3 заряда, текущий заряд 80 %, яркость 100 %, цвет Race Orange:

```
L,1,1,3,80,100,3,255,64,0
```

Контроллер не взведён, Boost неактивен, 3 заряда, заряд полный, пониженная яркость, синий:

```
L,0,0,3,100,40,10,0,0,255
```

### 3.2. Поля кадра

| № | Имя | Диапазон | Назначение |
|---|---|---|---|
| 0 | `L` | литерал | Признак кадра. Строки, не начинающиеся с `L,`, игнорируются. |
| 1 | `armed` | `0` или `1` | Двигатели взведены. |
| 2 | `boost` | `0` или `1` | Boost **расходует заряд** в данный момент. Не является признаком разблокировки. |
| 3 | `remain` | `0`…`20` | Число оставшихся зарядов, включая текущий. `0` — заряды исчерпаны. |
| 4 | `pct` | `0`…`100` | Остаток **текущего** заряда в процентах. В покое — `100`; при активном Boost снижается до `0`. |
| 5 | `bright` | `0`…`100` | Значение `ledstrip_brightness`. Компоненты RGB в кадре **не** масштабированы. |
| 6 | `id` | `0`…`15` | Индекс цвета палитры Betaflight **только для светодиода 0**. |
| 7 | `r` | `0`…`255` | Красная составляющая светодиода 0. |
| 8 | `g` | `0`…`255` | Зелёная составляющая светодиода 0. |
| 9 | `b` | `0`…`255` | Синяя составляющая светодиода 0. |

Длина строки не превышает **40** символов, включая `\n`.

### 3.3. Сведения, отсутствующие в кадре

- Массив цветов по светодиодам не передаётся. На контроллере может быть задано до 64 светодиодов; по UART передаётся **только светодиод 0**. Вся лента Arduino окрашивается этим цветом либо анимация строится на его основе.
- Мигание Boost в RGB **не** кодируется. При активном Boost контроллер не обнуляет RGB. **Мигание формирует Arduino** при `boost == 1`.
- Контрольная сумма, порядковый номер и метка времени отсутствуют.
- Обороты двигателей, напряжение и флаги режимов, кроме `armed` и `boost`, не передаются.

Строка с неверным числом полей отбрасывается; сохраняется предыдущий достоверный кадр.

## 4. Цвет (`id` и RGB)

Значения RGB уже преобразованы. Для WS2812 рекомендуется:

```text
пиксель = (r, g, b) × (bright / 100)
```

Поле `id` необязательно (поиск в палитре, цвет команды). Цвет Race по умолчанию — Orange, `id = 3`.

| `id` | Имя в CLI |
|---:|---|
| 0 | BLACK |
| 1 | WHITE |
| 2 | RED |
| 3 | ORANGE |
| 4 | YELLOW |
| 5 | LIME_GREEN |
| 6 | GREEN |
| 7 | MINT_GREEN |
| 8 | CYAN |
| 9 | LIGHT_BLUE |
| 10 | BLUE |
| 11 | DARK_VIOLET |
| 12 | MAGENTA |
| 13 | DEEP_PINK |

Значения `id` 14–15 возможны при изменённой палитре Status.

Источник цвета на контроллере зависит от `ledstrip_profile`:

| Профиль | Источник |
|---|---|
| **Race** (типовой) | `ledstrip_race_color` (либо цвет канала VTX, если Race = BLACK) |
| **Beacon** | `ledstrip_beacon_color` |
| **Status** | цвет **светодиода 0** во вкладке LED Strip |

Arduino не анализирует выбранный профиль и использует поля `r`, `g`, `b`.

## 5. Обязательное поведение Arduino

### 5.1. Контроль связи

При отсутствии достоверного кадра в течение **200 мс**:

- состояние трактуется как потеря связи с контроллером;
- рекомендуется выключить все светодиоды либо отобразить последний цвет с пониженной яркостью;
- мигание Boost **прекращается**.

### 5.2. Яркость

Масштабирование выполняется на Arduino:

```text
R_вых = r × bright / 100
G_вых = g × bright / 100
B_вых = b × bright / 100
```

Допускается целочисленная арифметика.

### 5.3. Мигание в режиме Boost (обязательно)

При `boost == 1` лента мигает с частотой **4 Гц**, скважность **50 %** (125 мс включено / 125 мс выключено), что соответствует значению по умолчанию `rpm_limit_boost_led_hz`.

- фаза «вкл»: масштабированный RGB;
- фаза «выкл»: все пиксели `0, 0, 0`.

При `boost == 0` цвет постоянный, мигание отсутствует.

Визуальные сигналы beeper и маяк контроллера по UART не передаются и на Arduino не воспроизводятся.

### 5.4. Дополнительные функции (не обязательны)

- `remain` — индикация числа зарядов (первые N светодиодов либо короткие вспышки при ARM);
- `pct` — сокращающаяся шкала при расходе заряда;
- `armed == 0` — пониженная яркость или медленное дыхание; `armed == 1` — полная яркость `bright`.

### 5.5. Лента

- Библиотека: FastLED или Adafruit NeoPixel.
- Порядок цветов WS2812 по умолчанию — **GRB**.
- Выводы данных ленты в примере комплекта: **D9, D10, D5, D6**. Не использовать D0, D1 и D4.
- Число светодиодов задаётся при компиляции (`NUM_LEDS`, как правило 1…64).
- При отсутствии дополнительной анимации все светодиоды имеют одинаковый цвет.

### 5.6. Алгоритм приёма

```
цикл:
  пока есть байты приёмника (в примере — fcSerial):
    добавить байт в буфер
    если байт равен '\n':
      если строка начинается с "L,":
        разделить по запятой
        если получено ровно 10 полей:
          разобрать целые числа → состояние
          запомнить время приёма
      очистить буфер
  если с последнего кадра прошло более 200 мс:
    режим потери связи
  иначе:
    рассчитать RGB
    при boost — мигание 4 Гц
    вывести на ленту
```

Буфер без символа `\n` длиной более 48 байт отбрасывается.

## 6. Смысл полей Boost (только для индикации)

Расчёт физики Boost на Arduino не выполняется. Отображается переданное состояние.

- `boost == 1` — заряд расходуется; требуется мигание; `pct` снижается от 100 к 0;
- по окончании заряда `boost` принимает значение `0`, `remain` уменьшается на 1, `pct` возвращается к 100 при наличии оставшихся зарядов;
- `remain == 0` и `boost == 0` — заряды исчерпаны; отображается постоянный цвет команды;
- обратный отсчёт разблокировки **не** передаётся; до разрешения Boost поле `boost` остаётся равным `0`.

В сборке SPEC зафиксированы пределы 12 000 / 13 600 об/мин, 3 заряда по 5 с и задержка 10 с. Arduino эти величины не использует.

---

## 7. Запрещается

- формировать WS2812 на паде LED контроллера со стороны Arduino: пад является выходом TX контроллера;
- ожидать двоичные кадры, последовательность CR-LF или префикс, отличный от `L`;
- ожидать 64 тройки RGB;
- использовать скорость 115200 бод (установлено 9600);
- требовать процедуру установления соединения: контроллер начинает передачу после загрузки при `ledstrip_output = UART`.

---

## 8. Приёмочные испытания

1. При `ledstrip_output = UART`, сигнале контроллера на **D4** Arduino и общем GND порт принимает строки `L,…` с частотой около 20 Гц.
2. Смена цвета Race в Betaflight изменяет `id` и `r,g,b` не позднее чем через 100 мс.
3. При ARM поле `armed` принимает значение `1`.
4. При активном Boost поле `boost` принимает значение `1`, лента мигает с частотой около 4 Гц, `pct` убывает.
5. При отключении линии TX контроллера не позднее чем через 200 мс лента переходит в состояние потери связи (выключена или приглушена), «залипшее» мигание отсутствует.
6. При DISARM во время Boost поле `boost` принимает значение `0`, мигание прекращается.
